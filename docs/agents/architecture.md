# Архитектура и источники

## Карта репозитория

| Путь | Назначение и способ изменения |
|---|---|
| `build.py` | Генератор HTML, компоненты, содержимое страниц, варианты формы. Изменять тексты и разметку здесь, затем собирать. |
| `site.json` | Контакты, домен, география, настройки формы для сборки по умолчанию. Не содержит секретов. |
| `seo.py` | Canonical, JSON-LD, режим индексации, sitemap, настройки Метрики. |
| `marketing/seo-pages.json` | Источник заголовков, описаний и списка подготовленных к индексации страниц. |
| `dist/*.css`, `dist/app.js`, `dist/analytics.js` | **Исходные** стили и клиентские скрипты, несмотря на имя папки. |
| `dist/assets/`, `dist/favicon.svg`, `dist/og.png`, `dist/.nojekyll` | Исходные ресурсы, лицензия шрифта и маркер статического хостинга. |
| `dist/**/index.html`, `dist/404.html`, `dist/robots.txt`, `dist/sitemap.xml`, `dist/documents/*.{txt,csv}` | Производные сборки. HTML в `dist/documents/` также генерируется. Не исправлять вручную. |
| `routes.json` | Генерируется `build.py` в корне даже при внешнем `OUTPUT_DIR`. |
| `verify.py` | Проверка метаданных, микроразметки, локальных ссылок и соответствия sitemap. |
| `scripts/build_hosting.py` | Архив для PHP-хостинга: стандартная структура или REG.RU. |
| `server/public/` | Публичная точка входа PHP и конфигурация веб-сервера/PHP. |
| `server/private/contact/` | SMTP-обработчик, пример конфигурации, обслуживание и vendored PHPMailer. На хостинге находится вне корня сайта. |
| `server/tests/integration.py` | Локальный HTTP/PHP + тестовый SMTP-приёмник. |
| `scripts/check_marketing.mjs` | Браузерные проверки аналитики, формы и размеров экрана с подменёнными внешними сервисами. |
| `marketing/direct-plan.json` | Источник рекламных черновиков; экспортирует `scripts/prepare_marketing.py`. |
| `marketing/direct-import/`, `ads-preview.md`, `seo-map.csv`, `validation.json` внутри `marketing/` | Производные рекламного экспорта; обновлять через скрипт. |
| `.github/workflows/` | Проверки SMTP и публикация GitHub Pages. Это не FTP-деплой. |

## Особенности текущей сборки

`dist/` смешивает исходники и результат. **Нельзя очищать или удалять её целиком.** `build.py` копирует её при заданном отдельном `OUTPUT_DIR`, затем перезаписывает HTML. Для проверки удалённых страниц нужен новый, пустой каталог вывода: оставшийся старый HTML может пережить сборку.

В `build.py` главная сначала собирается из `HOME`, затем перезаписывается редакционной версией `EDITORIAL_HERO`. Финальные замены, добавление стилей и версий ресурсов находятся в конце файла. При рефакторинге сравнивайте итоговые страницы до/после, а не только первый вызов `write_page`.

CSS подключается последовательно: `styles.css`, `pages.css`, `editorial.css`, `refinements.css`. Проверяйте каскад и адаптивные правила. Не добавляйте очередной конфликтующий override, если можно исправить действующее правило.

Версия ресурсов в HTML вычисляется из файлов `dist/`. Адреса ссылок и CSS меняются для `BASE_PATH`. Проверяйте и корень домена, и префикс GitHub Pages. При таком режиме задавайте отдельный `OUTPUT_DIR`, чтобы не записать префиксы обратно в исходный CSS.

## Режимы

| Режим | Форма | Индексация | Аналитика |
|---|---|---|---|
| Локальная сборка по умолчанию | Из `site.json`, сейчас FormSubmit | `noindex` | Выключена |
| GitHub Pages | FormSubmit, PHP там не работает | `noindex`, canonical основного домена | Выключена |
| REG.RU через `build_hosting.py` | Собственный `/api/contact.php` | Для текущей основной версии явно `INDEXING_ENABLED=1` | Без `METRICA_ID` выключена |

Ожидается 23 HTML-страницы `index.html`; 17 разрешены к индексации в основной SEO-сборке. Это контрольные значения текущего состава, не запрет добавлять страницы. Обновляйте их при согласованном изменении маршрутов. `projects`, `documents`, `privacy`, `request`, `thanks`, `404` остаются вне индекса.

## Форма и данные

`app.js` получает токен на том же сервере, отправляет поля и необязательный файл; обработчик валидирует данные, ограничивает частоту и отправляет письмо через PHPMailer. SMTP-пароль и защитный секрет задаются только приватным `config.php` на хостинге. Сборщик копирует приватную часть по явному списку, без `config.php` и `runtime/`.

Успех формы означает ответ обработчика после принятия письма SMTP-сервером. Повторный токен не должен повторно отправлять письмо. Ошибка сохраняет поля в открытой форме; они не сохраняются в localStorage. Условия и ограничения — в [SMTP-инструкции](../smtp-hosting.md).

`analytics.js` активен только при заданном счётчике и согласии посетителя. Вебвизор отключён. Поля заявки, имена файлов и произвольные параметры URL не передаются в события. `/thanks/` сам по себе не создаёт конверсию. Не подменяйте `form_submit_success` нажатием кнопки отправки.
