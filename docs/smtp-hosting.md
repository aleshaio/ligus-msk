# Лигус: собственная форма и SMTP

Подготовлен пакет сайта для PHP-хостинга. Формы на главной и `/request/` отправляют заявку и один файл на **tender@ligus-msk.ru** через SMTP. Внешние конструкторы форм, CAPTCHA и JavaScript-библиотеки для этого не используются.

## Что потребуется от хостинга

- Веб-сервер и почтовая инфраструктура в России; размещение сайта, почты, резервных копий и журналов нужно подтвердить у провайдеров. Российское название провайдера само по себе этого не подтверждает.
- PHP 8.2 или новее с `openssl`, `mbstring`, `fileinfo`, `pdo_sqlite`, `zip`.
- Исходящие SMTP-соединения, действующий TLS-сертификат сайта, возможность хранить папку вне document root.
- SMTP: адрес сервера, порт, режим STARTTLS/SSL, логин, пароль, разрешённый адрес отправителя. Пароль в репозиторий не помещать.
- Лимит письма не менее 15 МБ: файл до 10 МБ после кодирования увеличивается примерно на треть.

## Структура архива

```text
ligus-hosting/
  public_html/              ← только эта папка доступна по HTTP
    api/contact.php
    .user.ini
    ...страницы и ресурсы
  private/contact/         ← вне public_html
    config.example.php
    handler.php
    check.php
    maintenance.php
    vendor/phpmailer/
```

1. Загрузить пакет с сохранением структуры; document root домена — `public_html`. Не размещать весь архив в существующей публичной папке. Приватная папка должна быть соседней с document root.
2. Скопировать `private/contact/config.example.php` в `config.php`, заполнить SMTP и `site_origin` (точный HTTPS-адрес без завершающего `/`). Для `www` настроить редирект на основной домен. Получатель по умолчанию — `tender@ligus-msk.ru`.
3. Сгенерировать `secret`: `php -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'`. Установить `enabled => true` только после настройки.
4. Права: `config.php` — `600`, приватная папка и `runtime` — `700`, владелец — пользователь PHP. Если у хостинга другой режим пользователей, доступ к файлам согласовать с поддержкой; не ставить `777`.
5. Проверить `php private/contact/check.php`. Команда проверяет конфигурацию и расширения, но **не отправляет письмо**. Убедиться, что приватная папка недоступна через HTTP, включая другие домены аккаунта.
6. В PHP установить `upload_max_filesize=10M`, `post_max_size=12M`, `memory_limit=128M`. `.user.ini` включён для PHP-FPM/CGI; на другом режиме параметры задаёт хостинг. Лимит веб-сервера на тело запроса — минимум 12 МБ. По возможности задать `upload_tmp_dir` в закрытой папке аккаунта.
7. Каждые 15 минут запускать `php /полный/путь/private/contact/maintenance.php` через планировщик хостинга. Команда удаляет технические записи старше 1–2 часов и временные файлы старше часа, оставшиеся после аварийного завершения PHP. Очистка также выполняется при обращениях к обработчику.
8. После подключения отправить тестовую заявку с PDF с сайта и подтвердить получение в почте. Настроить SPF/DKIM/DMARC по инструкции почтового провайдера. Переход на `/thanks/` означает принятие письма SMTP-сервером, а не гарантию попадания во «Входящие».

В production разрешены только SMTP с TLS/SSL и авторизацией; проверка сертификата не отключается. Незашифрованный SMTP предусмотрен исключительно для локальных тестов на `127.0.0.1`/`::1`.

## Сборка и проверки

```sh
python3 scripts/build_hosting.py
# Результат: release/ligus-hosting.zip
PHP_BIN=php python3 server/tests/integration.py
```

SMTP-секреты, `runtime` и пакет `release` исключены из Git. Сборщик копирует приватные файлы по явному списку; настоящий `config.php` не попадёт в архив.

GitHub Pages обслуживает только статические файлы и не запускает PHP. Публичная версия пока использует прежний FormSubmit; пакет для российского хостинга собирается отдельно с `FORM_PROVIDER=smtp`. Перед переключением нужно перенести **весь сайт**, привязать домен и проверить почту. Нельзя просто заменить action у формы на GitHub Pages. MX и почтовые DNS-записи при переезде сайта не менять без инструкции почтового провайдера.

## Поведение и ограничения

- Сервер повторно проверяет обязательные поля, длины, телефон, email и согласие. Получатель и отправитель задаются только конфигурацией; пользовательский email используется как Reply-To.
- Запросы ограничены по хешу IP (5 попыток за 10 минут) и суммарно (120 за час). За общим IP учреждения лимит общий. Текущая версия не доверяет `X-Forwarded-For`; при размещении за прокси потребуется настройка доверенных прокси у веб-сервера, иначе лимит будет общим для всех.
- Origin/Referer, подписанный временный токен и скрытое поле препятствуют межсайтовым отправкам и простому спаму. Это не полная защита от ботов/DDoS; общий предел защищает почту ценой временной недоступности формы при атаке.
- Проверяются размер, расширение и содержимое вложения; Office ZIP не распаковывается, макросы внутри DOCX/XLSX не принимаются. Это не антивирус. PDF, DOC и XLS могут содержать опасное содержимое — проверка вложений почтовым антивирусом остаётся задачей провайдера.
- Текст заявки не сохраняется в отдельной базе. В SQLite остаются только хеш IP, случайный ID, время и статус; вложение удаляется после попытки отправки. PHP и веб-сервер могут вести собственные журналы — их состав и сроки настраиваются на хостинге. В PHP-лог не выводятся поля формы, пароль и подробности SMTP-ошибок.
- Повтор с тем же токеном после успешной отправки не создаёт второго письма. Если SMTP-соединение оборвалось, результат может быть неопределённым: автоматическая повторная отправка блокируется, в интерфейсе остаются введённые данные и контакты компании. Письмо в этом случае могло быть принято сервером.
- Ошибка сети сохраняет поля в открытой форме. Они не пишутся в localStorage и пропадут при перезагрузке. Для работы формы нужен JavaScript.
- До запуска остаются реквизиты оператора, отдельный текст согласия и утверждение сроков хранения писем/резервных копий. Существующие `noindex` и пометки демонстрационных проектов сохранены. Код сам по себе не подтверждает выполнение правовых обязанностей.

Почтовая библиотека: PHPMailer **7.1.1**, LGPL 2.1. Исходник, лицензия и SHA-256 файлов находятся в `vendor/phpmailer/SOURCE.json` и `LICENSE`. Composer на хостинге не нужен.
